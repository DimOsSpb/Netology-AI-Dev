### Блок 6.2 — Планирование агента

#### Что делаем

Наивный агент из ДЗ Б6.1 (`app/services/agent_naive.py` с тремя tools и `for`-циклом по `max_steps`) превращается в управляемый ReAct-агент с лимитами и self-reflection. Tool-описания переписываются по чек-листу проектирования инструментов: имя-глагол, `description`, отвечающий на четыре вопроса, строгая JSON Schema. Добавляются `max_iterations`, `timeout` на итерацию, лимит ревизий после критики. Цель — получить агента, который перестаёт галлюцинировать tool_calls и не уходит в runaway-цикл, а если ошибается — ловит ошибку через self-reflection до того, как сформирует ответ пользователю.

Инкремент ложится рядом: новый `app/services/agent_react.py` живёт отдельным модулем, старый `agent_naive.py` остаётся нетронутым как baseline для сравнения. Канон модуля — openai>=2.0 Chat Completions, модель gpt-5.4-mini (премиум-шаг генерации — gpt-5.4); LangGraph здесь ещё не нужен.

#### Задачи

1. **Новый модуль рядом с baseline.** Создаётся `app/services/agent_react.py` рядом со старым `agent_naive.py`. Старый файл не трогается — он остаётся baseline для сравнения и регрессионного контроля.
2. **Реализовать ReAct-цикл.** Цикл Thought → Action → Observation → Thought собирается поверх `client.chat.completions.create(...)` с `tools=[...]` и `tool_choice="auto"`, модель gpt-5.4-mini. Системный промпт задаёт поведение ReAct явно: рассуждение перед действием (одно предложение о том, что и зачем делается), ровно один инструмент за шаг, условие остановки (данных достаточно → финальный ответ без вызова инструментов), запрет выдумывать данные при пустом результате и честный отказ, когда доступными инструментами задачу не решить. Формат Thought/Action/Observation держит сам API нативного tool calling — в промпт его зашивать не нужно (это отличает нативный ReAct от текстового, где формат парсится из ответа модели). Каждый шаг логируется: номер итерации, выбранный tool, аргументы, observation, latency, токены.
3. **Два жёстких лимита.** Добавляются `max_iterations` (по умолчанию 10, диапазон 8–20) и `timeout_per_iteration_sec` (5–15 сек на один LLM-вызов + tool execution). При превышении любого лимита возвращается явное сообщение "Превышен лимит итераций" или "Timeout", без молчаливого зависания.
4. **Self-reflection (Reflexion-light).** После каждой tool observation выполняется отдельный LLM-вызов critic (дешёвая модель — gpt-5.4-mini), который читает observation и текущий план и пишет короткий вердикт OK или `REVISE: <причина>`. Если REVISE — следующая итерация ReAct получает этот фидбек в system-приписке, а премиум-шаг генерации можно поднять до gpt-5.4. Лимит ревизий — 2 на один запуск; счётчик ревизий не сбрасывается между итерациями.
5. **Подсчёт стоимости.** На каждом LLM-вызове фиксируются `prompt_tokens`, `completion_tokens`, `total_tokens` (включая critic). Итог по запуску складывается в `dict`, который возвращается вместе с ответом, и дублируется в `structlog`.
6. **5 тестовых задач, два прогона.** Готовятся 5 задач из домена диплома: 2 простых (1 tool, 1–2 итерации), 2 средних (composability — выход одного tool идёт во вход другого), 1 «провокационная», где правильное поведение — НЕ вызывать tool вовсе. Каждая задача прогоняется дважды: на `agent_naive.py` и на `agent_react.py`.
7. **Отчёт docs/agent-react-report.md.** Заполняется таблица сравнения по всем 5 задачам: задача, итераций naive, итераций react, корректность ответа naive (да/нет), корректность ответа react (да/нет), всего токенов naive, всего токенов react, сработала ли ревизия. Под таблицей — 3–5 наблюдений в свободной форме: где reflection помог, где оказался лишним, где старый агент уходил в цикл.

#### Критерии самопроверки

* `agent_react.py` падает с явным сообщением при `max_iterations` и `timeout`, а не висит.
* Self-reflection срабатывает не больше 2 раз за запуск; счётчик не сбрасывается между итерациями.
* Каждая итерация логируется отдельной записью с номером шага, tool name, latency и токенами.
* На «провокационной» задаче agent_react отвечает без вызова tools; agent_naive, скорее всего, всё-таки вызвал.
* В отчёте `docs/agent-react-report.md` есть строка по каждой из 5 задач и подсчёт total tokens (input + output) по обоим агентам.
* `agent_naive.py` нетронут, его прогон воспроизводится — это baseline для сравнения.
* В коде нет `max_iterations >= 30` and нет `additionalProperties: true`.

#### Референсы

* [Anthropic Tool Use Best Practices](https://www.anthropic.com/engineering/writing-tools-for-agents "Writing effective tools for AI agents — Anthropic") — чек-лист по tool descriptions и строгой `input_schema`.
* [ReAct Paper (Yao et al., 2022)](https://arxiv.org/abs/2210.03629 "ReAct: Synergizing Reasoning and Acting in Language Models") — оригинальный паттерн Thought/Action/Observation.
* [Reflexion Paper (Shinn et al., 2023)](https://arxiv.org/abs/2303.11366 "Reflexion: Language Agents with Verbal Reinforcement Learning") — verbal feedback и episodic memory.
* [OpenAI Function Calling Guide](https://developers.openai.com/api/docs/guides/function-calling "Function calling | OpenAI API") — `tool_choice`, `strict: true`, формат `tool_calls`.
* [Anthropic — Building Effective Agents](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools "Define tools - Claude Platform Docs") — когда вообще нужен агент, а когда хватит промпта.
* [Plan-and-Execute Agents (LangChain)](https://www.promptingguide.ai/techniques/react "ReAct Framework & LangChain") — альтернатива ReAct: план из N шагов заранее, полезно для обоснования выбора паттерна.
