## Выбор моделей для эмбеддингов
 
- В анализе буду смотреть облачные модели и локальные модели
- Модель выбиралась по:
  - качеству retrieval
  - языковой поддержке
  - размерности embedding
  - скорости
  - стоимости
  
### Облачные модели

| Модель                        | Почему                                  |
| ----------------------------- | --------------------------------------- |
| text-embedding-3-small        | облачный baseline                       |
| text-embedding-3-large        | максимум качества OpenAI                |

### Локальные модели

| Модель                        | Почему                                  |
| ----------------------------- | --------------------------------------- |
| Qwen3-Embedding-4B            | самая мощная модель в семантическом поиске |
| Qwen3-Embedding-0.6B          | современная open-source, компактная     |


## Архитектура решения

Для унификации взаимодействия с embedding-моделями использован OpenAI-compatible API. Локальные модели разворачиваются через llama.cpp + GPU tesla v100 16GB, что позволяет использовать единый интерфейс с облачными и локальными embedding-провайдерами. 
Модуль app.services.embeddings предоставляет публичный интерфейс embed_texts(), реализованный методом класса Vectorizer

## Итоговый выбор

Для RAG-системы диагностики инфраструктуры выбрана модель:  

text-embedding-3-large  

Причины выбора:  

- максимальное качество retrieval (86.67%);
- максимальный retrieval margin (0.086);
- хорошая производительность после прогрева;
- стабильное разделение релевантного и нерелевантного контекста.

Несмотря на более высокую стоимость по сравнению с локальными моделями, качество поиска является критическим фактором для диагностической системы.  
При этом локальные модели qwen3 могут быть использованы как вариант для автономного deployment, где приоритетом является отсутствие внешних API-затрат.

## Вывод

Проведенное тестирование показало, что выбор embedding-модели должен основываться не только на стоимости или размере вектора, а прежде всего на качестве retrieval в конкретной предметной области.

Для задачи диагностики Linux/Kubernetes/Proxmox инфраструктуры наиболее подходящим вариантом является text-embedding-3-large, обеспечивающий лучший баланс качества поиска и производительности.

Интересный вывод по локальным моделям на llama.cpp + tasla v100 16GB - Медленней облачных провайдеров в 2 раза. Причина понятна - это 10 летнее отставание в технологии (Volta), Современные GPU в 2026 работают с моделями на порядки быстрее. 2 раза разницы - это накладные на задержки при работе с облачными провайдерами. Т.о. при наличии современных GPU у компании, для embedding может дать существенное ускорение и экономию т.к. 
стоимость индексации может быть незначительной, а вот 10 000 диагностических запросов в месяц в проде становятся постоянными расходами.
